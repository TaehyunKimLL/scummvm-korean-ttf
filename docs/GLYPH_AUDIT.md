# SCUMM 게임별 재활용 코드 감사 (2026-09-07)

`0x00..0x7f` 전 범위를 `~/games/fullaudit.py`로 렌더해서 눈으로 확인한 결과.
4개 코드만 추측했을 때는 Indy3의 진짜 언더스코어와 MI2의 `0x40/0x5b-0x5d/0x60/0x7b-0x7e`를
놓쳤다. 표는 **본 것만** 적는다.

## 시트 위치

`~/games/audit/<game>-<file>-cs<N>.png` (31장 + v3/v4 추가분).
재생성: `python3 ~/games/auditall.py`

## 파서 (`fullaudit.py` load())

| 게임 버전 | 파일 | 방식 |
|---|---|---|
| v3 (Indy3) | `99-no.lfl` | 2바이트 크기 접두사, 고정 8바이트/글리프 1bpp. `charsetlib.parse_v3` |
| v4 (MI1/Loom) | `90N.LFL` | 오프셋 테이블. `charscan.parse_charset` 통째로 |
| v5/v6 (MI2/Indy4/DOTT) | `*.001` | XOR 0x69, CHAR 블록 |
| v7 (FT/DIG) | `*.LA1` | XOR 없음, CHAR 블록 |

## 확인된 재활용 코드

| 게임 | charset | 0x07 | 0x5e | 0x5f | 0x7f | 기타 |
|---|---|---|---|---|---|---|
| MI1 | 902 (대사) | 해골 | 점3개 | 좌화살표 | 우화살표 | `0x40`=대시, `0x5b-0x5d`=`< = >`, `0x60`=블록, `0x7b-0x7e`=악센트 |
| MI2 | cs1 (대사) | 해골 | 점3개 | 좌화살표 | 우화살표 | MI1 902와 **글리프 100/100 동일** |

| DOTT | cs1 | 해골 | 점3개 | 좌화살표 | (빈칸) | `0x74`=십자, `0x40`=대시 |
| FT | cs1 | 없음 | **빈칸** | **빈칸** | **빈칸** | 라틴 대문자만 있는 폰트 |
| DIG | cs1 | 없음 | 점3개 | **원형 심볼** | 빈칸 | 화살표 아님 |

## 결론

1. **게임별 고정이고 번역과 무관.** 영문 원본 DOTT·일본어 MI2를 덤프해도 같은 코드에 같은 그림.
   → 사용자가 ini에 쓸 성질이 아니다.
2. **하지만 게임마다 다르다.** Indy3의 `0x5f`는 진짜 언더스코어, DIG는 원형, FT는 빈칸.
   → v5/v6 전체 일괄 적용은 **틀린다**. 게임 ID 화이트리스트가 맞다.
3. **MI1 902 == MI2 cs1** (글리프 100개 완전 일치). 한글 번역판이 폰트를 공유했다.
4. **FT는 조치 불필요** — 해당 코드가 폰트에 없으므로 `glyphIndex()`가 실패해 자동 폴백.

## 주의

`DIG.LA1 cs0`은 `h=5 bpp=4`로 파싱되는데 **오탐**이다. 렌더 결과가 노이즈.
`cs1`(h=11 bpp=2)이 진짜 대사 폰트. 헤더 자동 탐색이 첫 번째 그럴듯한
오프셋을 잡는 한계 — 시트가 읽히지 않으면 다른 charset 인덱스를 볼 것.
