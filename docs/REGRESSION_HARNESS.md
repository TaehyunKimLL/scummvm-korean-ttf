# 회귀 안전망 (regression harness)

작성: 2026-09-05. 리팩토링/재정렬이 렌더링을 깼는지 픽셀로 판정하기 위한 장치.

## 왜 필요한가

앞으로 할 작업(히스토리 재구성, CJKTextMode 도입, 출력 추상화)은 모두
"동작은 그대로, 구조만 바꾼다"가 전제다. 그 전제를 **증명**하지 못하면
리팩토링이 아니라 도박이다. 그런데 눈으로 스크린샷을 비교하는 방식은
이미 여러 번 오판을 낳았다.

## 핵심 설계: "차이 0"을 기대하지 않는다

게임 화면에는 애니메이션이 있어 **같은 바이너리로 두 번 캡처해도 픽셀이
다르다**. 그래서 먼저 노이즈 바닥을 재고, 그 바닥을 넘는 차이만 회귀로 본다.

```
base   ← 기준 빌드 1회차
base2  ← 같은 빌드 2회차   ... base vs base2 = 노이즈 바닥
new    ← 변경 후 빌드      ... base vs new 를 바닥과 대조
```

## 도구

| 파일 | 역할 |
|---|---|
| `~/games/regress.sh` | 타깃 15종을 캡처해 `/tmp/regress/<런>/` 에 저장 |
| `~/games/rgdiff.py` | 두 런을 비교, 노이즈 바닥 대비 회귀 판정 |
| `~/games/settle.sh` | 특정 타깃이 정지 화면에 도달하는 시각 실측 |
| `~/games/smoke.sh` | 타깃이 부팅되는지만 빠르게 확인 |
| `~/games/addja.sh` | CJK/대조군 타깃을 scummvm.ini 에 등록 |

```sh
~/games/regress.sh base                       # 기준선
~/games/regress.sh base2                      # 노이즈 바닥용
~/games/regress.sh new /path/to/other/scummvm # 변경 후
python3 ~/games/rgdiff.py base base2                  # 바닥 측정
python3 ~/games/rgdiff.py base new --noise base2      # 회귀 판정
```

## 함정과 대처 (실측으로 확인한 것)

### 1. CD 오디오 경고 대화상자

FM-Towns 일본어판은 트랙 파일(`*.fla`)은 있는데 `CDDA.SOU` 가 없으면
모달 대화상자가 떠서 **게임이 시작조차 안 된다**. 처음 측정에서
`ja-loom`/`ja-zak`/`ja-mi1` 이 23,213px 씩 차이 났던 진짜 원인이
이것이었다 — 애니메이션이 아니라 **대화상자 테마 색이 런마다 달랐다**.

대처: 빈 파일 생성. `: > ~/games/<타깃>/CDDA.SOU`
적용 대상: `loomja` `zakja` `mi1ja` `loomtg16ja` `mi1towns`

### 2. 인트로 애니메이션

캡처 시각만 늦춰서는 안 된다. `regress.sh` 가 `xdotool` 로 Esc 를
반복 전송해 컷신을 건너뛴다 (`SKIP_KEYS`). `xdotool` 이 없으면
이 스킵이 조용히 실패하므로 설치 필수.

### 3. 정지 화면이 없는 타깃

`ja-indy4` 는 인트로를 지나도 배경 네온사인이 계속 깜빡여 노이즈 바닥이
**36,000px (56%)** 다. 화면 자체는 양쪽 런이 같은 장면이다.
→ `rgdiff.py` 는 바닥이 5,000px 을 넘는 항목에 대해 절대값이 아니라
   **바닥의 1.5배**를 기준으로 판정한다.

### 3-1. 노이즈 바닥은 하한일 뿐 — 절대 하한이 따로 필요하다

바닥이 0 인 항목도 다음 런에서 수백 px 이 바뀐다. 캐릭터가 다른 걸음에
서 있기 때문이다. 처음에는 `max(2*바닥, 바닥+200)` 만 썼는데, 그 결과
**바이너리 md5 가 완전히 같은 두 런에서 3 건이 "회귀 후보"로 오탐**됐다:

| 항목 | 변경 px | 바닥 | 실제 원인 |
|---|---|---|---|
| `i3-multi_t30` | 538 | 0 | 인물 걷기 프레임 |
| `i3-multi_t40` | 564 | 279 | 〃 |
| `i3-2x_t40` | 1,712 | 680 | 〃 |

→ `ABS_FLOOR = 2500` 을 도입했다. 이 값 이하는 어떤 경우에도 회귀로
   보지 않는다. 도입 후 동일 바이너리 조합 2 가지에서 **회귀 0 건**.

**교훈**: 하네스 자체를 먼저 검증해야 한다. 동일 바이너리로 두 런을
비교해 0 건이 나오는지 확인하지 않으면, 이후 모든 판정이 노이즈에
묻힌다. `bin_md5` 를 manifest 에 기록하는 이유가 이것이다 — 두 런의
바이너리가 같은지 즉시 확인할 수 있어야 오탐을 구분한다.

### 4. PC-Engine 은 아예 못 돌린다

`ja-loompce`/`en-loompce` 는 `palette.cpp` 의 `assert(_gdi)` 로 죽는다.
**upstream master 에서도 동일하게 죽는 것을 확인**했으므로 우리 회귀가
아니다. 타깃 목록에서 제외했고, 별도 upstream 버그 리포트 후보다.

### 5. 빌드 구성이 트리마다 다르다

`~/src/scummvm` 은 `ENABLE_SCUMM_7_8 = 1`, `/tmp/svm-master`(대조군)는
꺼져 있다. 헤더를 옮기는 변경은 **양쪽 구성에서 다 빌드해봐야** 한다.

### 6. 기준선은 타깃 목록이 바뀌면 무효다

`regress.sh` 의 타깃을 15 → 19 로 늘린 뒤 옛 `base`(30장) 와 새
`verbfix`(38장) 를 비교했더니 **11 건이 회귀로 떴다**. 그중에는
`en-mi1towns`(영어) 와 `ja-mi2`(일본어) 처럼 우리 수정(`isKoreanHiRes()`
안에만 있음)이 닿을 수 없는 타깃도 있었다.

원인: 두 런의 캡처 시각과 타깃 구성이 달라 게임 진행 위치가 어긋났다.
`manifest.txt` 의 `bin_md5` 로 확인 가능하다 (`8fd9d44e` vs `480eb1a3`).

**규칙**: `regress.sh` 의 TARGETS 나 캡처 시각을 바꾸면 기준선을 반드시
다시 뜬다. 비교하는 두 런은 같은 스크립트 버전으로 캡처해야 한다.

### 7. LLM 시각 판정이 픽셀보다 정확한 경우가 있다

MI2 동사 소실 건에서 **픽셀 총량은 우리 쪽이 402px 더 많았다**
(4,036 vs 3,634). 배경 박스 색 때문이다. 총량만 봤으면 "우리가 더
그렸다"고 넘어갔을 것이다.

`vision_analyze` 로 나란히 보여주니 즉시 "왼쪽 동사 칸이 비었다"고
지적했다. 4 가지 케이스(동일 바이너리 2, 실제 차이 2)에서 4/4 정답.

권장: 픽셀로 전수 스캔해 후보를 추리고, 그 후보만 LLM 에 넘겨 판정한다.
단 LLM 판정은 비결정적이므로 회귀 게이트가 아니라 보조 신호로 쓴다.
